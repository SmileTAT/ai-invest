## 1. 背景与问题

个人投资者做研究面临三个结构性痛点：

1. **信息过载且分散**：行情、财报、公告、研报、新闻、社区情绪散落在十几个平台，
   人工汇总一只股票的完整画像需要数小时。
2. **分析能力不对称**：机构有分析师团队和量化工具，个人投资者只有 K 线图和碎片化观点，
   决策严重依赖情绪与二手信息。
3. **现有工具两极分化**：传统炒股软件（同花顺/东方财富/富途）强在行情弱在深度研究；
   专业终端（Bloomberg/Wind/Choice）价格昂贵（数万元/年）且面向机构。

LLM 的成熟（长上下文、工具调用、多智能体协作）第一次让"个人拥有一个 AI 分析师团队"
在成本上可行——这是本项目的核心机会窗口。

## 2. 产品定位

> **给个人投资者的 AI 研究员团队**：输入一只标的或一个组合，
> 输出机构级的、可解释、有数据溯源的研究报告。

明确**不做**什么（边界即护城河的一部分）：

- ❌ 不做自动交易/代客理财（合规风险极高，需牌照）
- ❌ 不做行情终端（红海，拼不过既有玩家）
- ❌ 不做"荐股"（输出的是研究框架与依据，决策权归用户）

## 3. 目标用户

| 画像 | 特征 | 付费意愿 |
|---|---|---|
| P0：严肃个人投资者 | 资产 10 万–500 万，每周花 3h+ 做研究，用过雪球/同花顺付费功能 | 高（已有付费习惯） |
| P1：投资内容创作者 | 需要快速产出个股分析内容的博主/UP主 | 高（生产工具） |
| P2：小型私募/投顾团队 | 3–20 人，买不起 Wind 全套，需要研究提效 | 很高（B 端预算） |

## 4. 竞品与差异化

| 竞品 | 强项 | 弱项（我们的切入点) |
|---|---|---|
| 同花顺 i问财 / 东财 Choice AI | 数据全、入口大 | AI 是"问答插件"，非深度研究流水线；结论少溯源 |
| 雪球 | 社区与观点 | 观点噪声大、无结构化分析 |
| Bloomberg / Wind | 专业、全面 | 贵、面向机构、无 LLM 原生体验 |
| 开源方案（FinGPT、TradingAgents 等） | 免费、可定制 | 面向开发者，无产品化体验，数据需自己接 |

**差异化定位**：多智能体研究流水线（基本面/技术面/情绪/风控四个角色交叉验证）+
每个结论可点击展开数据溯源。卖的不是数据，是**结构化的研究过程**。

## 5. MVP 范围（第一个可收费版本）

### 5.1 核心功能（P0，必须有）

1. **个股深度研究报告**
   - 输入：股票代码（首期支持 A 股 + 美股）
   - 流水线：数据采集 → 四个分析智能体并行研究 → 风控智能体交叉质询 → 汇总报告
   - 输出：结构化报告（估值、财务质量、趋势、情绪、风险清单、多空论点对照）
   - 每个论点附数据来源与时间戳
2. **自选股监控简报**：每日盘后对自选股生成"今天发生了什么 + 是否影响原有论点"的增量简报
3. **账号体系 + 用量计费基础设施**（为变现做准备，见 §8）

### 5.2 明确推迟（P1+）

- 组合层面分析（相关性、行业暴露、再平衡建议）
- 财报电话会/公告的自动解读与提醒
- 回测与策略验证
- 移动端

### 5.3 成功指标

- 激活：注册用户 7 日内生成 ≥ 3 份报告的比例 > 40%
- 留存：周留存 > 25%
- 质量：报告"有用"评分（用户打分）> 4.0/5
- 单位经济：单份报告 LLM 成本 < ¥2（通过模型分级与缓存控制）

## 6. 系统架构（概要）

```
数据源适配层 (akshare / yfinance / 财报API / 新闻RSS)
        ↓  统一 schema + TimescaleDB 落库 + Redis 缓存
研究流水线 (编排器)
  ├── 基本面智能体   ├── 技术面智能体
  ├── 情绪面智能体   └── 风控智能体（对前三者交叉质询）
        ↓  结构化 JSON（tool_use 强制 schema）
报告服务 (FastAPI) → 前端 (Next.js) / API 输出
```

工程规范与技术选型细节见根目录 `CLAUDE.md`。

### 关键技术决策

- **成本控制是生死线**：路由分级——数据整理用小模型，核心推理用强模型；
  同一标的当日报告缓存复用；prompt 缓存降低重复上下文成本。
- **数据是最大外部依赖**：MVP 用免费/低价源（akshare、yfinance），
  适配器接口设计成可热替换，商业化后升级付费数据源（聚宽/Tushare Pro/Polygon）。
- **可解释性即产品**：溯源不是附属功能，是核心卖点，架构上从第一天支持
  （每个智能体输出必须引用 evidence id）。

## 7. 路线图

| 阶段 | 时间 | 里程碑 |
|---|---|---|
| M1 | 第 1–6 周 | 数据适配层 + 单智能体报告跑通（能出第一份报告） |
| M2 | 第 7–10 周 | 四智能体流水线 + 溯源 + Web 端 → **内测** |
| M3 | 第 11–14 周 | 自选股简报 + 账号/计费 → **公测 + 开始收费** |
| M4 | 第 15 周+ | 按 §8 变现路径逐条验证，数据驱动取舍 |

## 8. 变现路径分析 💰

按"验证成本从低到高"排序，建议依次验证而非同时铺开：

### 路径 1：C 端订阅（主路径，M3 启动）

- **模式**：免费层（3 份报告/月，限基础模型）→ Pro ¥68/月（不限量+强模型+自选股简报）
  → Max ¥198/月（组合分析+优先队列+导出）
- **对标锚点**：同花顺 Level-2 约 ¥50–200/月，雪球私房课更贵——用户已被教育过付费。
- **关键假设**：报告质量差异肉眼可见。验证方式：公测期 A/B 免费层转化率，目标 > 5%。
- **天花板**：中等（C 端投研付费盘子有限），但现金流启动最快。

### 路径 2：API / 报告即服务（M4，边际成本极低）

- **模式**：把研究流水线以 API 形式卖给下游——投资社区、券商 App 的内容板块、
  自媒体工具商。按报告份数或 token 计价。
- **优势**：复用同一套引擎，无需新研发；B 端单价高（¥1–5/份 × 万级调用量）。
- **验证方式**：公测期主动接触 2–3 家投资内容平台谈 PoC。

### 路径 3：创作者工具（P1 用户群变现）

- **模式**：面向财经博主的"研究底稿生成器"——报告一键转图文/视频脚本大纲，
  按月订阅（¥199–399/月，生产工具定价高于消费工具）。
- **优势**：创作者自带传播，天然是获客渠道（报告带水印 = 免费广告）。

### 路径 4：小 B（私募/投顾）团队版（验证周期最长，客单价最高）

- **模式**：团队工作区 + 私有部署选项 + 自定义数据源接入，¥2–5 万/年/团队。
- **前提**：C 端打磨出的报告质量是销售 Demo；需要 1 个种子客户共创。

### 不建议的变现方向（明确排除）

- **卖信号/荐股服务**：在中国大陆需投资咨询牌照，无牌照做是红线；有牌照则模式变重。
- **导流开户返佣**：与"中立研究"定位冲突，损伤信任根基。
- **广告**：用户量级不支撑，且污染研究场景。

### 合规底线（所有路径共同前提）

- 所有输出带免责声明，定位"研究工具"而非"投资建议"。
- 若未来涉及大陆投顾业务需申请牌照，或与持牌机构合作（路径 4 的合理演化）。
- 数据源的商业使用授权在商业化前必须逐一确认（akshare/yfinance 的免费数据
  多数**不可直接商用**，这是路径 1 启动前必须解决的问题）。

## 9. 风险清单

| 风险 | 等级 | 缓解 |
|---|---|---|
| 数据源商用授权缺失 | 🔴 高 | M3 前完成付费数据源替换预算与谈判 |
| LLM 成本失控 | 🟠 中 | 模型分级路由 + 缓存 + 单报告成本监控告警 |
| 报告质量不稳定（幻觉） | 🔴 高 | 强制溯源 + 风控智能体交叉质询 + 数值类结论必须来自计算而非 LLM 生成 |
| 监管（投顾定性） | 🟠 中 | 严守"工具"定位，法务审阅对外文案 |
| 大厂跟进 | 🟡 低-中 | 深耕研究流水线的深度与溯源体验，快速迭代 |
